# speedtest-interner

Консольный скрипт на Python 3.8+ (только стандартная библиотека, ставить ничего не нужно).
Делает 10 последовательных запросов к адресу, дожидается полного ответа на каждый
и печатает среднее время запроса, общий объём и скорость скачивания.

## Запуск

Адрес вводить не нужно, достаточно выбрать размер файла (1, 5, 10, 25 или 100 МБ):

```bash
python3 speedtest.py            # файл 10 МБ по умолчанию
python3 speedtest.py -s 1       # файл 1 МБ
python3 speedtest.py -s 100     # файл 100 МБ
```

Свой адрес тоже можно передать, он главнее `-s`:

```bash
python3 speedtest.py https://example.com/big.jpg
```

Дополнительные параметры: `-n` — число запросов (по умолчанию 10),
`-t` — лимит на один запрос в секундах (по умолчанию 60),
`-d` — пауза между запросами в секундах (по умолчанию 0, в замер скорости не входит).

Во время загрузки в терминале показывается живой прогресс (сколько скачано и процент),
чтобы на медленном канале было видно, что скрипт работает.

10 запросов по 100 МБ — это около 1 ГБ трафика, на медленном канале это долго,
для быстрой проверки берите `-s 1` или `-s 10`. Для честного замера нужен файл
от 10 МБ: на коротких загрузках сильнее влияет установка соединения.

Готовые адреса: Cloudflare (`speed.cloudflare.com/__down?bytes=...`) для 1–25 МБ
и Hetzner (`nbg1-speed.hetzner.com/100MB.bin`) для 100 МБ. Это сторонние серверы,
они могут перестать работать, тогда передайте свой адрес.

## Единицы измерения

- Скорость: **Мбит/с** (мегабиты в секунду, 1 Мбит = 10^6 бит) — так обычно указывают
  тариф провайдера. Для справки рядом выводится и **МБ/с** (1 МБ = 10^6 байт).
- Время запроса: секунды.
- Объём данных: мегабайты (МБ).

## Как считается

- Время каждого запроса — от отправки до полного получения тела ответа (`time.perf_counter`).
- Скорость = (общий объём в битах) / (суммарное время всех запросов).
- Неудачные запросы выводятся в stderr и в подсчёт не входят.
- Единица скорости подбирается автоматически (бит/с, Кбит/с, Мбит/с, Гбит/с),
  поэтому и очень медленный, и очень быстрый канал выводится читаемо.
- Если замер слишком короткий (меньше 0,1 с суммарно или меньше 100 КБ данных),
  скорость не выводится: таймер на таких интервалах неточен и цифра была бы
  недостоверной. Скрипт предложит взять файл побольше и завершится с кодом 2.
- Лимит на один запрос — 60 с (меняется флагом `-t`), так что на очень медленном
  канале скрипт не зависнет. Параметр `-t 120` увеличит лимит.
- Пустой ответ сервера и отсутствие успешных запросов дают ошибку, а не «0 Мбит/с».
- `Ctrl+C` прерывает замер и показывает результат по уже выполненным запросам.
- В запрос добавляется `Cache-Control: no-cache`, чтобы промежуточные кэши мешали меньше.
